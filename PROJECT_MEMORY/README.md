# PROJECT_MEMORY — память проекта «Service Company»

Эта папка — источник правды о проекте для агента/разработчика. Здесь хранится
актуальное состояние проекта и история изменений. Она нужна, чтобы восстановить
контекст без повторного изучения всего кода.

## Правила

1. **Всегда обновляй** `overview.md`, когда меняется архитектура/логика/структура.
2. **Всегда дописывай** запись в `changes.md` после любого завершённого изменения.
3. Изменение считается «завершённым», когда код написан/исправлен и проверен.
4. Если файл `overview.md` устарел — перепиши его целиком, а не правь кусками.
5. Формат записей в `changes.md`: `[ГГГГ-ММ-ДД] Описание (файлы/что менялось)`.
6. Не выносить статические подсказки и предупреждения в интерфейс админки — они
   должны быть в документации/настройках проекта.

## Файлы

| Файл | Содержание |
|---|---|
| `overview.md` | Текущее состояние: архитектура, стек, эндпоинты, модели, потоки бота, нюансы |
| `changes.md` | Хронологический лог изменений (append-only) |
| `README.md` | Этот файл |

## Стартовые факты (сверено 2026-11-25, подробности — в `overview.md`)

- Название проекта: **«Service Company»** (автосервис, кузовной ремонт/PDR).
- Проект находится в git-репозитории (`.git/`); реальный `.env` не коммитится.
- Рабочий канал — **VK**: клиентский бот на `vkbottle`. Старый код удалён из
  папки проекта 2026-11-25; в compose его нет.
- Админка — веб-интерфейс FastAPI по адресу `http://localhost:8000/admin`;
  вход по `HMAC_SECRET` (заголовок `x-admin-secret`). В боте админ-панели нет.
- Боевой стек: FastAPI + vkbottle + Celery + Postgres + Redis
  (docker-compose; MinIO остался в compose, но кодом не используется).
- Напоминания о записях уходят в VK через Celery Beat; для уведомлений админу
  нужен `ADMIN_VK_ID` в `.env`.
- Заявки на оценку вмятин в коде отсутствуют (только таблицы в первой миграции);
  исторические записи в `changes.md` не отражают текущее состояние.
