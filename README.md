# «Service Company» — система записи и учёта автосервиса

Клиенты записываются на услуги через VK-бота; администратор ведёт услуги, записи,
журнал работ, статистику и расписание через веб-админку. Бэкенд — FastAPI,
клиентский бот — vkbottle, фоновые напоминания — Celery.

## Сервисы

| Сервис | Стек | Порт | Назначение |
|---|---|---|---|
| `postgres` | postgres:15 | 5432 | БД `autoservice` |
| `redis` | redis:7 | — | кэш/брокер Celery |
| `minio` | bitnamilegacy/minio | 9000 / 9001 | S3-хранилище в compose; текущим кодом не используется (9001 — консоль) |
| `backend` | FastAPI, SQLAlchemy(async), Alembic | 8000 | REST API (`/docs`) + веб-админка (`/admin`) |
| `vk_bot` | vkbottle | — | клиентский бот ВКонтакте + уведомления админу в VK |
| `celery_worker` | Celery + Beat | — | напоминания о записях в VK |

## Требования

- Docker + Docker Compose
- Корневой файл `.env` (образец — `.env.example`)

> ⚠️ Реальный `.env` содержит секреты и не коммитится (см. `.gitignore`) —
> при клонировании создайте его из `.env.example`.

## Быстрый старт

```bash
# 1. Создать конфигурацию и указать свои секреты
cp .env.example .env

# 2. Собрать и поднять все сервисы
docker compose up -d --build

# 3. Применить миграции БД (при первом запуске и после новых ревизий)
docker compose exec backend alembic upgrade head

# 4. Проверить бэкенд
curl http://localhost:8000/health          # → {"status":"ok"}
# Swagger-документация API: http://localhost:8000/docs
```

После этого VK-бот начинает поллить сообщества. Клиенты пишут в сообщество,
администратор заходит в веб-админку.

### Первый вход админа

1. Укажите в `.env` `ADMIN_VK_ID` — VK id администратора (или отрицательный id
   беседы), куда бот будет слать уведомления о новых записях и отменах.
2. Откройте `http://localhost:8000/admin`.
3. Введите `HMAC_SECRET` из `.env` — он используется как пароль админки и
   передаётся в заголовке `x-admin-secret`.
4. После входа доступны вкладки: обзор, клиенты, услуги, записи, работы,
   расписание и контакты.

> ⚠️ Не публикуйте `8000` в интернет без HTTPS: пароль админки передаётся в
> заголовке запроса. Для прода лучше закрыть порт фаерволом или поставить
> reverse proxy с TLS.

## Установка VK-бота

VK-бот даёт клиентам записаться на услугу прямо в сообществе ВКонтакте
(услуга → автомобиль → дата → время → телефон → подтверждение). Это основной
канал проекта. Управление сервисом — через веб-админку `http://localhost:8000/admin`;
админ-панели внутри VK нет и не планируется. Уведомления о записях и отменах
приходят администратору в VK (`ADMIN_VK_ID`).

### 1. Создать сообщество (если его ещё нет)

Заведите публичное сообщество ВКонтакте (или используйте существующее) —
именно от его имени будет работать бот.

### 2. Включить Сообщения сообщества

В настройках сообщества: **Управление → Сообщения** → включить приём
сообщений от пользователей.

### 3. Получить токен доступа сообщества

**Управление → Работа с API → Ключи доступа** → «Создать ключ» с правами
**Сообщения (messages)** — скопируйте токен, это и есть `VK_GROUP_TOKEN`.

`VK_GROUP_ID` — числовой ID сообщества (виден в URL страницы сообщества или
в том же разделе «Работа с API»).

### 4. (рекомендуется) Отключить стандартные ответы сообщества

**Управление → Сообщения → Настройки** — выключите приветственное сообщение
и «умные ответы» сообщества, чтобы они не конфликтовали с ответами бота.
Бот сам присылает приветствие на первое сообщение.

### 5. (рекомендуется) Включить кнопку «Начать»

Там же, в настройках сообщений, включите кнопку **«Начать»** — она отправит
боту служебное первое сообщение, и он сразу покажет главное меню.

### 6. Заполнить `.env` и перезапустить

```bash
# в .env:
VK_GROUP_TOKEN=полученный-токен-сообщества
VK_GROUP_ID=числовой-id-сообщества
ADMIN_VK_ID=ваш-vk-id-или-отрицательный-id-беседы

docker compose up -d --build vk_bot   # или docker compose restart vk_bot, если контейнер уже был поднят
docker compose logs -f vk_bot         # в логе должно появиться «VK-бот Service Company запускается...»
```

Без `VK_GROUP_TOKEN` контейнер `vk_bot` не падает и не перезапускается по
кругу — он просто ждёт (в логе будет предупреждение), пока токен не появится.

### 7. Проверить

Напишите сообществу от лица обычного (не админского) VK-аккаунта — бот
должен ответить приветствием с клавиатурой «🔧 Записаться / 📋 Мои записи /
📞 Контакты». Пройдите запись до конца — она появится в базе клиентов, в
веб-админке и уведомлением администратору в VK (`ADMIN_VK_ID`).

Напоминания за `remind_hours` / `remind_hours_2` тоже приходят в VK: Celery
выбирает аккаунты с `platform='vk'` и шлёт сообщения через VK API от имени
сообщества. Метки `reminded_at` / `reminded_soon_at` выставляются только после
успешной отправки.

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Postgres (host `postgres` — имя compose-сервиса) |
| `REDIS_URL` | Redis |
| `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET_NAME` | MinIO; в текущем коде не используется |
| `VK_GROUP_TOKEN`, `VK_GROUP_ID` | VK-бот и напоминания — токен сообщества и его ID |
| `ADMIN_VK_ID` | VK id администратора (или отрицательный id беседы) для уведомлений |
| `HMAC_SECRET` | пароль веб-админки (`x-admin-secret`) |
| `ENCRYPTION_KEY` | зарезервирован для шифрования (сейчас кодом не используется) |
| `BACKEND_INTERNAL_URL` | внутренний URL бэкенда для бота/Celery (`http://backend:8000`) |

### Генерация секретов

Для `ENCRYPTION_KEY` и `HMAC_SECRET` нужны разные случайные строки. Сгенерируйте
каждую отдельно и положите в `.env` (реальный `.env` в git не попадает):

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Если локального Python нет, то же можно сделать в контейнере:

```bash
docker run --rm python:3.11-slim python -c "import secrets; print(secrets.token_urlsafe(32))"
```

> ⚠️ **Честно о текущем состоянии.** `HMAC_SECRET` используется как пароль
> веб-админки: фронтенд передаёт его в заголовке `x-admin-secret`, бэкенд
> сравнивает его через `hmac.compare_digest`. Заголовок `admin-id` больше
> не принимается. `ENCRYPTION_KEY`
> по-прежнему только объявлен в конфиге: шифрования нет, телефоны, госномера и
> VIN лежат в Postgres в открытом виде. После внедрения шифрования потеря ключа
> сделает эти поля невосстановимыми — храните `.env` и бэкапы бережно.

## Резервное копирование

Минимальный набор: том `postgres_data` и файл `.env`. Том `minio_data` тоже стоит
сохранять, хотя сейчас MinIO кодом не используется. Том `redis_data` — кэш и
брокер, его можно не бэкапить (потеряется только временное состояние меню
клиентов и очереди Celery).

Логический дамп Postgres (можно делать на работающем сервисе):

```bash
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > autoservice.sql
```

Восстановление:

```bash
cat autoservice.sql | docker compose exec -T postgres psql -U autoservice -d autoservice
```

Снимок томов (остановите сервисы, чтобы данные не менялись). Имена томов зависят
от имени папки проекта — здесь пример для `service_company`; актуальные имена
смотрите в `docker volume ls`:

```bash
docker compose down

docker run --rm \
  -v service_company_postgres_data:/data \
  -v /path/to/project:/backup \
  alpine tar czf /backup/postgres_data.tgz -C /data .

docker run --rm \
  -v service_company_minio_data:/data \
  -v /path/to/project:/backup \
  alpine tar czf /backup/minio_data.tgz -C /data .

docker compose up -d
```

`/path/to/project` замените на абсолютный путь к папке проекта (`%cd%` в cmd,
`$PWD` в PowerShell). Восстановление тома — той же командой с `tar xzf` вместо
`tar czf` (перед этим очистите `/data`). Файл `.env` скопируйте отдельно в
защищённое место: без него боты и бэкенд не запустятся, и его нельзя хранить в git.

## Разработка

Код всех сервисов подмонтирован в контейнеры, поэтому правки применяются без
пересборки — достаточно перезапустить сервис:

```bash
docker compose restart vk_bot          # после правок VK-бота
docker compose restart backend         # после правок API или веб-админки (без --reload)
docker compose restart celery_worker   # после правок напоминаний
docker compose logs -f vk_bot          # логи VK-бота
docker compose logs -f celery_worker   # логи напоминаний
```

### Тесты

Автотестов пока нет — проверка вручную через `http://localhost:8000/admin`
и тестовую запись из сообщества.

## Полезное

- Веб-админка: http://localhost:8000/admin (пароль — `HMAC_SECRET`)
- Health-чекаут бэкенда: `GET /health`
- Swagger: http://localhost:8000/docs (админ-эндпоинты требуют `x-admin-secret`)
- Минио-консоль: http://localhost:9001 (логин/пароль из `.env`; MinIO сейчас кодом не используется)
- Celery Beat рассылает напоминания в VK за `remind_hours` / `remind_hours_2`
  (настраивается в веб-админке, вкладка «Настройки»). Воркер берёт аккаунты с
  `platform='vk'`; уведомления мастеру о новых записях и отменах тоже приходят
  в VK на `ADMIN_VK_ID`.
- Таймзона сервиса: настраивается в админке «🕐 Расписание» → «🌍 Таймзона» IANA-именем
  (например, `Europe/Moscow`; по умолчанию `UTC`). Часы работы, календарь слотов и
  нерабочие даты задаются в этой таймзоне. В БД время хранится в UTC, а API, боты и
  напоминания показывают его уже в таймзоне сервиса. При смене таймзоны старые записи
  не пересчитываются — меняется только их отображение.
